# Play Store Deployment

How the Pantry App is signed, built, and deployed to the Google Play
Store via GitHub Actions CI/CD.

## Overview

When a tag matching `v*.*.*` (e.g. `v0.0.5`) is pushed to the repository,
the `.github/workflows/deploy-to-playstore.yml` workflow:

1. Runs `flutter analyze` and `flutter test`.
2. Injects the `.env` file from GitHub Secrets.
3. Decodes the upload keystore and signing properties.
4. Builds a signed release AAB and APK.
5. Uploads both to the Google Play Console internal track.

## Prerequisites (manual, one-time)

### Google Play Console

1. Create a Google Play Console account.
2. Create an app with package name `com.thigas_tech.pantry_app`.
3. **Upload the first AAB manually** — Google requires the initial release
   to be created through the Play Console UI. After the first upload, the
   CI workflow can update it on every tag push.
4. Create an internal test track (optional but recommended for CD).

### Google Cloud service account

The CI workflow uses a Google Cloud service account to authenticate with
the Play Console API.

1. Go to the Google Cloud Console and create a project (or use an existing one).
2. Enable the **Google Play Android Developer API**.
3. Create a service account (IAM > Service Accounts > Create).
4. Assign the role **Service Account User** to it.
5. Generate a JSON key and download it.
6. In the Google Play Console, go to **Users and permissions**.
7. Invite the service account email with the **Release Manager** role.

The JSON key content is stored as `PLAY_STORE_SERVICE_ACCOUNT` in GitHub
Secrets.

## Signing setup

### Play App Signing (recommended, default)

Google manages your **release key**. You only need an **upload key**, which
is the one you generate locally. If you lose the upload key, Google can
issue a replacement.

This is the default for all new Play Console accounts. No action needed —
the keystore you generate IS the upload keystore.

### Generate the upload keystore

```bash
keytool -genkey -v \
  -keystore upload-keystore.jks \
  -alias upload \
  -keyalg RSA -keysize 2048 \
  -validity 10000
```

- **storePassword**: password for the keystore file
- **keyPassword**: password for the key (usually same as storePassword)
- **keyAlias**: `upload` (or any name you choose)

### Encode for GitHub Secrets

```bash
base64 -w0 upload-keystore.jks > keystore_base64.txt      # ANDROID_KEYSTORE_BASE64
```

Create `android/key.properties` from the template (see
`android/key.properties.template` in the repo), fill in real values, then:

```bash
base64 -w0 android/key.properties > keyprops_base64.txt    # KEY_PROPERTIES_BASE64
```

Do NOT commit the real `key.properties` — it is `.gitignore`d. The template
file (`key.properties.template`) with placeholder values IS committed.

## GitHub Secrets

All secrets are stored in **Settings > Secrets and variables > Actions**.

| Secret | Format | Source |
|---|---|---|
| `ANDROID_KEYSTORE_BASE64` | Base64 of `upload-keystore.jks` | Generated by `keytool` |
| `KEY_PROPERTIES_BASE64` | Base64 of `key.properties` | Template filled with real values |
| `PLAY_STORE_SERVICE_ACCOUNT` | Plain text JSON key | Google Cloud IAM |
| `OFF_USER_ID` | String | Open Food Facts account |
| `OFF_PASSWORD` | String | Open Food Facts account |
| `CONTACT_EMAIL` | String | User contact |
| `FEEDBACK_TOKEN` | String | GitHub PAT with repo scope |

## CI/CD workflow

File: `.github/workflows/deploy-to-playstore.yml`

Triggers on: workflow dispatch (tag push trigger is currently commented out
pending Play Console document verification).

Steps:
1. Checkout + Flutter setup
2. `flutter analyze --fatal-infos --fatal-warnings`
3. `flutter test --concurrency=2`
4. Inject `.env` from secrets
5. Decode `ANDROID_KEYSTORE_BASE64` → `android/upload-keystore.jks`
6. Decode `KEY_PROPERTIES_BASE64` → `android/key.properties`
7. `flutter build appbundle --release`
8. `flutter build apk --release`
9. Upload AAB to Play Console internal track

Both AAB and APK artifacts are available as workflow artifacts (90-day
retention).

## Version codes

The Play Store requires every release to have a strictly higher
`versionCode` than the previous one.

`pubspec.yaml` uses the `version: X.Y.Z+N` format where `N` is the build
number used as `versionCode` on Android. Increment `N` with every release
tag.

```yaml
# pubspec.yaml
version: 0.0.5+2   # versionCode = 2
```

The CI workflow does NOT validate version code monotonicity — that is the
developer's responsibility before pushing the tag.

## Tag conventions

| Tag | pubspec version | Meaning |
|---|---|---|
| `v0.0.5` | `0.0.5+1` or higher | Release to Play Store |
| Any other tag | — | Ignored by deploy workflow |

Pushing a tag matching `v*.*.*` will trigger deployment. Make sure the
tag matches the `pubspec.yaml` version (before the `+`).

## First-time manual upload

Google requires the first release for a new app listing to be uploaded
manually through the Play Console web UI. The CI workflow can only
**update** an existing listing.

Steps for first upload:
1. Build locally: `flutter build appbundle --release`
2. Upload `build/app/outputs/bundle/release/app-release.aab` via
   Play Console > App > Production > Create new release
3. Fill in the release notes, content rating, privacy policy, etc.
4. Submit for review

After this, the CI workflow uploads to the **internal track**. Promotion
from internal to production is done manually in the Play Console.

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `401 Unauthorized` from upload action | Wrong service account or missing API | Check service account has Release Manager role, API is enabled |
| `APK signature is invalid` | Keystore mismatch | Regenerate keystore or contact Google for key reset |
| Build fails in CI | Missing or malformed secrets | Verify base64 encoding: `echo "$SECRET" \| base64 -d` |
| `versionCode 1 already exists` | Duplicate version code | Increment `+N` in pubspec.yaml |
| Workflow not triggered | Tag doesn't match `v*.*.*` | Use semantic version tags only |
| First upload rejected | Missing content rating, screenshots, etc. | Fill in all Play Console requirements |
