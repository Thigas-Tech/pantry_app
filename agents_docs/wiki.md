# GitHub Wiki & API Documentation

How the Pantry App GitHub Wiki is set up, kept in sync, and how doc
comments feed it.

## Overview

The GitHub Wiki at `github.com/Thigas-Tech/pantry_app/wiki` serves the
API documentation generated by [dart doc]. Every public class, method,
constructor, and field with a `///` doc comment appears in the wiki.

The wiki is **automatically updated on every push to `main`** by the
`.github/workflows/wiki.yml` CI job.

## How doc comments become the wiki

1. `dart doc .` reads every `///` doc comment in the source tree.
2. It generates static HTML files in `doc/api/`.
3. The CI workflow copies those files into the wiki repository.
4. GitHub Wiki renders the HTML.

**Garbage in, garbage out.** Write doc comments as proper sentences —
they are the user-facing API documentation.

## Doc comment conventions (brackets, not backticks)

[dart doc] treats `[square brackets]` as **cross-references**. It resolves
the name inside brackets to a known symbol (class, method, typedef, etc.)
and emits a clickable link in the generated HTML.

Backticks `` ` `` in doc comments are rendered as **inline code** — plain
monospace text with no link. This is how Markdown works, and [dart doc]
follows the same pattern.

| What you write | What dart doc generates |
|---|---|
| `Uses [DatabaseHelper] to read data.` | Clickable link to the DatabaseHelper page |
| `Uses `DatabaseHelper` to read data.` | Plain monospace text, no link |
| `See [MyClass.myMethod].` | Clickable link to myMethod on MyClass |
| `Pass a [http.Client] for testing.` | Clickable link to the http.Client class |

**Rule**: when referencing public API, use brackets `[]`. Only use backticks
for literal code values (`true`, `null`, `"string"`, `42`).

When the `comment_references` lint fires, add the missing import — never
switch to backticks to silence it.

## Wiki structure

```
wiki/
  Home.md                  Hand-maintained landing page
  _Sidebar.md              Navigation sidebar (hand-maintained)
  _Footer.md               Footer text (hand-maintained)
  index.html               Auto-generated by dart doc
  __404error.html          Auto-generated by dart doc
  categories.json          Auto-generated by dart doc
  index.json               Auto-generated by dart doc
  config/                  Auto-generated by dart doc
  database_*/              One directory per library
  ...
```

**The three `*.md` files are the only manually maintained wiki content.**
Everything else is overwritten on every CI run.

## Manual wiki update

If CI is unavailable or you need to push wiki changes directly:

```bash
# Clone the wiki repo (first time)
git clone git@github.com:Thigas-Tech/pantry_app.wiki.git /tmp/wiki

# Regenerate docs and push
dart doc .
cd /tmp/wiki
cp -r /path/to/project/doc/api/* .
git add -A && git commit -m "Update API docs" && git push
```

## CI/CD automation

See `.github/workflows/wiki.yml` for the full workflow.

The workflow:
1. Triggers on push to `main` (and manual `workflow_dispatch`).
2. Checks out the source repository.
3. Runs `flutter pub get` and `dart doc .`.
4. Clones the wiki repository.
5. Removes all auto-generated content from the wiki (preserving `Home.md`,
   `_Sidebar.md`, `_Footer.md`, and the `.git` directory).
6. Copies `doc/api/*` into the wiki root.
7. Commits and pushes to the wiki repository.

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| Wiki shows old docs | CI didn't run or failed | Manually trigger via Actions tab |
| `dart doc` has warnings | Missing imports for bracket references | Add the import, re-run `dart doc .` |
| Broken links in wiki | Bracket reference targets a private symbol | Only use brackets for public API |
| Wiki clone fails | Token permission issue | Ensure `GITHUB_TOKEN` has `contents: write` |
| `comment_references` lint fires | Missing import | Add the import — never suppress the lint |
