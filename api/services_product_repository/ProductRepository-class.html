ProductRepository

ProductRepository class

The central data access point that implements the offline‑first pattern.

ProductRepository coordinates between the local SQLite cache (DatabaseHelper) and the remote API (OffAdapter).

Offline‑first strategy

For every product lookup:

  1. Check local cache – if the product exists in SQLite, return it immediately without any network call.
  2. Call primary API – if not cached, fetch from the remote service and store the result locally for future offline use.
  3. Error handling – if the API returns a ProductNotFoundException, rethrow it so the UI can react (e.g., redirect to OFF app). If a network error occurs, throw FetchFailedException.

Inventory management

The repository exposes CRUD methods for inventory items and for the named inventories (pantries) themselves. All item operations are scoped to a specific inventory via its InventoryItem.inventoryId.

Fallback API

The constructor accepts an optional fallback OffAdapter. This is currently unused but could be re‑enabled in the future if a second API is desired.
